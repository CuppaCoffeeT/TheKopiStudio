## Policy design (default recipe for this batch)

Most of these are low-sensitivity config / log tables. Default recipe:

- **Read**: `is_approved_user()` — all authenticated staff
- **Write**: `is_admin()` — admin only (configs should not be mass-edited)
- **Delete**: `is_admin()` only

Exceptions documented inline:
- `xero_oauth_tokens` → super_admin only (contains credentials)
- `agent_corrections` → writes allowed for any approved user (they log own corrections), reads admin-only
- Any table with PII → inherits stricter pattern from W15.01/.02

## Migration approach

Batch pattern (repeat per table):

```sql
-- Enable RLS first (many of these have it off entirely)
ALTER TABLE public.<t> ENABLE ROW LEVEL SECURITY;

-- Apply default recipe
CREATE POLICY "<t>_select_approved" ON public.<t> FOR SELECT TO authenticated USING (is_approved_user());
CREATE POLICY "<t>_write_admin"   ON public.<t> FOR INSERT TO authenticated WITH CHECK (is_admin());
CREATE POLICY "<t>_update_admin"  ON public.<t> FOR UPDATE TO authenticated USING (is_admin()) WITH CHECK (is_admin());
CREATE POLICY "<t>_delete_admin"  ON public.<t> FOR DELETE TO authenticated USING (is_admin());
```

Group by natural sub-batch (3–5 tables per PR) so each PR is reviewable.
