# Decisions — Kopi Studio direction handoff

_Last Updated: 2026-08-05 SGT_

## 2026-07-25 — Disabled controls keep `--fg-muted`; they are AA-exempt
**Decision**: A `disabled` button/input may keep `bg-muted` + `text-muted-foreground` (4.37:1) — do not "fix" it to `--fg-dim`. Only *enabled* small text must clear 4.5:1.
**Why**: WCAG 2.1 SC 1.4.3 explicitly exempts inactive user-interface components. Darkening a disabled label to `--fg-dim` (#5D4F3F, 7.34 on card) makes it read *more* prominent than the enabled labels around it and destroys the disabled affordance. Contrast audits keep re-flagging `RecipientPickerDialog.tsx` submit-blocked state on the raw ratio alone.
**Impact**: `--fg-dim` remains the correction for *enabled* 10–12px text on tinted surfaces (`CommandPalette` footer hints, `SearchableMultiSelect` overflow chip, `Alert` dismiss label). Disabled states stay on `--fg-muted`.

## 2026-07-25 — Borderless (`isBare`) triggers carry focus on a full-opacity ring
**Decision**: `SearchableMultiSelect`'s bare trigger open-state uses `ring-2 ring-ring` (full opacity), not the `ring-ring/15` halo the bordered variant uses.
**Why**: The bordered variant splits the job — `border-ring` carries the 3:1 SC 1.4.11 state change and the low-alpha ring is only a halo. A bare trigger has no border, so the ring is the *only* mark; brown at 30% over card composites to ~#DED3C4 (~1.4:1) and is effectively invisible.
**Impact**: Any future borderless control must use a full-opacity brown ring. The `border-ring` + `ring-ring/15` pair is only valid where a border actually exists.

## 2026-07-25 — Direction 2a "Kopi House" chosen
**Decision**: Apply direction 2a (quiet broadsheet on The Kopi Studio brand palette) from the Claude Design "Kopi Studio Directions" canvas, turn 2; 2b Ledger and 2c rejected.
**Why**: User pick (in-conversation, 2026-07-25). Keeps the broadsheet/hairline layout logic that was already approved on 2026-07-21 while moving it onto the actual client brand — brown stays punctuation (CTA, focus, index numerals) instead of flooding chrome; viz collapses to a single brown ramp.
**Impact**: Whole palette repoints navy/gold → page `#f0e6d6` / card `#faf6ee` / raised `#ffffff` / brown `#8b6a47` / sage `#5a7a5e` / border `#d9ccc0`. Type swaps Georgia → Instrument Serif (headings, never under 18px) + system-ui → IBM Plex Sans (body/UI), both loaded from Google Fonts via `<link>` in `index.html`, not `@fontsource`. Sidebar becomes a *light* rail (206px, card cream) rather than a dark one. Charts use the four-step brown ramp `#8b6a47`/`#a58868`/`#c0a68c`/`#dccbb6`. Spec: [KOPI_2A_SPEC.md](./KOPI_2A_SPEC.md).
**Supersedes**: 2026-07-21 — Direction 1a "Masthead" chosen ([../2026-07-21-visual-directions/decisions.md](../2026-07-21-visual-directions/decisions.md)). The 1a *structure* survives — dateline greeting masthead, hairline-carried layout, restricted accent, monochrome viz; only the palette and type stack are replaced.

## 2026-07-25 — Three AA text variants added on top of the brand card
**Decision**: Introduce `--brown-text` `#806241`, `--sage-text` `#526f56`, `--negative-text` `#ab4925`, used **only** for text under 18px. The raw brand hexes `#8b6a47` / `#5a7a5e` / `#d97551` remain authoritative for fills, borders, icons, chart marks, and display type ≥ 18px.
**Why**: The brand card's hexes are tuned as fills and miss WCAG AA (4.5:1) as small type. Measured: raw sage 3.88 on page / 4.45 on card; raw terracotta 2.57 / 2.95 — and the comp uses terracotta for live 13px cell text ("Overdue · 12 Jul"). Raw brown is the subtler failure: it passes on card (4.58) and fails on page (4.00), which would make compliance depend on which surface a component lands on. One variant per hue removes that conditional entirely. Variants preserve hue and were chosen to clear 4.5:1 on both surfaces at the smallest step (4.54 / 4.51 / 4.58 on page).
**Impact**: A documented, deliberate deviation from `kopi-studio-brand-card.html`, which does not carry these tokens. Applies to secondary button labels, form labels, links, sage/terracotta status text, and any small-text accent. Status **pills** are exempt — the comp's own pill text colours score better on their tints (`#4a6a54` on `#d9e8e0` = 4.76; `#7d5f3d` on `#f0e2cf` = 4.61) than the page-tuned variants would; only the error pill takes the correction (`#b04f2c` 4.17 → `#ab4925` 4.50).
**Open**: muted `#7d6b5b` measures **4.12 on the page colour** and the comp places it there (dateline, KPI meta, table meta). Not covered by the three variants; no fourth hex invented because none exists in the comp or brand card. Also open: the brand card's success button (`#faf6ee` on `#5a7a5e` = 4.45) is marginally below AA at 12.5px.

## 2026-07-25 — Light-pinned, no dark mode
**Decision**: Ship light only. No `prefers-color-scheme` variants, no theme toggle, no dark token set.
**Why**: The Kopi Studio brand is defined as a warm cream system — page → card → raised is a three-step *light* ladder, and the whole accent strategy (brown as punctuation on cream) inverts badly on dark. Neither the brand card nor any of the three explored directions defines a dark counterpart, so a dark theme would be invented rather than specified.
**Impact**: Removes the dark-surface token layer inherited from the navy/gold direction. Contrast ratios in [KOPI_2A_SPEC.md](./KOPI_2A_SPEC.md) are stated against `#f0e6d6` and `#faf6ee` only and need no second audit.

## 2026-07-25 — Comp wins layout, brand card wins palette
**Decision**: Where the 2a comp and the brand card conflict, follow the comp for layout/structure and the brand card for colour values — with each conflict recorded in the spec rather than silently resolved.
**Why**: The comp is the approved visual artefact and encodes decisions the brand card has no opinion on; the brand card is the client's own colour authority and outlives any single direction.
**Impact**: Three brand-card behaviours are explicitly **not** used in 2a — the `135deg` brown page-header gradient, the brown-filled active nav item (2a uses a 2px brown left border + `#f3ede3` fill + dark text), and brown-coloured section titles (2a renders all section heads `#3a2e24`). Two comp values override the brand card: card hover shadow warms from `rgba(0,0,0,0.1)` to `rgba(58,46,36,.1)`, and the input focus ring alpha goes from `0.1` to `.12`.

## 2026-07-25 — KPI delta tint alphas are set by the AA budget, not by taste
**Decision**: `--delta-positive-bg` drops from `rgb(90 122 94 / 0.14)` to `/ 0.10` and `--delta-negative-bg` from `rgb(217 117 81 / 0.16)` to `/ 0.12`. The foregrounds stay on the AA text variants (`--sage-text`, `--negative-text`).
**Why**: `KpiDeltaBadge` renders its label at 12px and always sits inside a `KpiTile`, which paints `bg-card` `#faf6ee`. At the original alphas the pairs measured **4.39** (sage) and **4.48** (terracotta) — both below 4.5:1, so the badge was the one place where the AA variants still failed. Deepening the text further would have broken hue parity with the three locked variants; thinning the tint one step fixes it from the other side: 4.60 and 4.68.
**Impact**: The delta chips read slightly quieter. These alphas are now a contrast budget, not a style choice — anything that deepens them must re-measure the fg/bg pair on `#faf6ee`. Comment in `src/index.css` (LOCKED_PICKS v1 → KpiTile) records the measurements.

## 2026-07-25 — AppBase Radix zinc + red 1–12 scales deleted from `@theme`
**Decision**: Remove `--color-zinc-1..12` and `--color-red-1..12` from `src/index.css`. Also removed the five dead Geist Pixel shape aliases (`--font-pixel-{square,grid,circle,triangle,line}`).
**Why**: Both scales are cool-grey / pure-red AppBase leftovers that fight the warm cream ground, their block still claimed "dark variants live under `.dark { … }` below" (there is no `.dark` block), and a repo-wide grep found **zero** consumers in `src`, `tests` or `docs`. Same for the font aliases. Keeping unreferenced retired-palette tokens invites a future component to reach for `bg-zinc-3`.
**Impact**: Tailwind's own `zinc-*` / `red-*` default palette is untouched — `bg-zinc-950`, `text-red-700`, `bg-red-50` still compile (verified in the built CSS), so the ~66 remaining default-palette utility usages elsewhere in `src` are unaffected and remain a separate migration item. `docs/01-system-architecture/design-system/COLORS.md` (line ~100) and `TYPOGRAPHY.md` still describe these tokens as present and still describe the navy/gold vocabulary — stale, needs the docs pass.

## 2026-07-25 — `AppSidebar` rail ships on card cream, not page cream
**Decision**: `AppSidebar` paints `bg-sidebar` (card cream `#FAF6EE`) with `--surface-subtle` `#F3EDE3` as the hover/current fill and `--tint-pressed` `#EBE2D4` as the pressed fill. KOPI_STUDIO_REDESIGN_PRD.md P2 says "200px, **page-bg** ground" — the width is taken, the ground is not.
**Why**: Four sources say card cream and one says page cream. The 2a comp's own markup sets the rail `background:#faf6ee` inside a `.k-card` whose background is the page `#f0e6d6`; KOPI_2A_SPEC "Layout language" states "the sidebar is the **lighter** surface"; this file's direction-2a entry says "Sidebar becomes a *light* rail … card cream"; and P1 shipped `--sidebar-background: 40 55% 96%` with the inline comment "card cream — matches `--card`" plus `--tint-pressed` labelled "nav `:active`". Decisive on top of that: idle nav items are `--fg-muted` `#7D6B5B`, which measures **4.72 on card cream and 4.12 on page cream** — the spec's own unresolved "Open item — muted on page". A page-cream rail would ship every idle nav label below AA.
**Impact**: The rail reads as a raised surface against the page, consistent with the light-theme cardinal rule. The active item is therefore `--surface-subtle` (one step down from the rail) rather than card cream, since card cream is now the ground. If the rail is ever moved to page cream, idle item colour must move to `--fg-dim` in the same change.

## 2026-07-25 — Account controls move into the sidebar footer; the top bar is retired
**Decision**: Delete the desktop masthead (`AppHeader` + `AppHeaderDesktopBar`) and re-home the user menu, notifications bell and ViewAs selector into a new `AppSidebarFooter` pinned to the bottom of the 200px rail. Below `lg`, `AppHeaderMobileBar` keeps the same controls (view-as folded into the account dropdown) and is the only horizontal bar left in the product.
**Why**: None of the three 2a comps draws a top bar — the rail is the entire chrome, and the content column starts at its own kicker/title. The comps only mock the content area, so they are silent on where account controls live; putting them in the rail footer is the only placement that keeps the content column matching the comps. Running both rail and masthead duplicated identity (two wordmarks, two "home" links) and navigation.
**Impact**: The rail is now the single home for identity, navigation and account. `useDashboardChrome` returns connector *prop bags* instead of pre-rendered slots so each home places its own overlays — the rail opens them `side="right"` (a 256–320px menu cannot hang off a 200px rail bottom-aligned). `ImpersonationBanner` deliberately stays in the content column at full page width: it is safety chrome, not account chrome. `AppHeaderMobileBar`'s breakpoint moved `md:hidden` → `lg:hidden` to match the rail, which had left 768–1023px with neither rail nor bar. Newly dead and deleted: `AppHeader.tsx`, `AppHeaderDesktopBar.tsx`, `AppHeaderWrapper`, the `ThemeMode` plumbing in `AppHeaderUserMenu` (light-pinned since 2026-07-25), and `AppHeaderShell`'s `onCmdKClick` + `notificationsSlotOverride` props, whose only sink was the desktop bar.

## 2026-07-25 — Breadcrumb is content, not chrome — and only where it adds information
**Decision**: The breadcrumb renders as quiet inline 12px text at the top of the content column (`DetailPageFrame` → `PageShellHero`'s breadcrumb slot; `AppHeaderShell` → above the H1). `ListPageFrame` renders none. `AppHeaderShell` renders one only when a page passes `breadcrumb` explicitly.
**Why**: The 2a Detail comp shows exactly this — plain "Clients / Marcus Tan" above the serif title, no bar — while the List and Dashboard comps show no crumb at all. `AppHeaderShell`'s default trail is `Workspace / <title>`, which would restate the H1 sitting directly beneath it.
**Impact**: Every existing `breadcrumb` prop API is unchanged, so no page needed editing. The trail is still built on list pages, but only to label `AppHeaderMobileBar`. `Breadcrumb` dropped to 12px and lost the bold current segment; earlier segments keep `--fg-dim` (not `--fg-muted`, which is 4.12:1 on the page cream).

## 2026-07-25 — Detail body is a `1.4fr / 1fr` grid, and the dossier panels are a primitive vocabulary
**Decision**: `PageShell`'s `withSideRail` body stops being a flex row of "2/3 main + fixed 300px aside" and becomes the comp's `grid-template-columns: 1.4fr 1fr` with 22px gaps, each column a 22px-gap flex column. The panels that fill it ship as `primitives/detail/dossier` — `DossierPanel` (uppercase 11px `.12em` `--fg-muted` label + cream card), `DossierStatGrid`, `DossierRampBar`, `DossierKeyValueList`, `DossierLoadingPanel` — and the CRM client Overview adopts them.
**Why**: The 2a Detail comp is a *dossier*, not a record page with a sidebar: the narrow column is a peer surface carrying reference data and transient states, so a fixed 300px rail (which does not scale with the pane) contradicts it. Making the panels primitives rather than per-feature markup keeps the label treatment, the 22px padding, the stat/list/prose label gaps and the ramp's series-order colour assignment in one place — the same reason the frame itself is a primitive.
**Impact**: `sideRailClassName` survives as a prop but its width utilities are inert under a grid (no page passes it today). `PageShellStatusPill` was split into its own file to keep `PageShell` under the LOC ceiling; `PageShellStatusTone` is still re-exported from `./PageShell`, the import path adopters know. The hero meta line and the status pill dropped `--font-mono` — 2a has no mono anywhere.

## 2026-07-25 — Dossier panels keep `Card`'s 16px radius, not the comp's 12px
**Decision**: `DossierPanel` composes the shell `Card` primitive (radius 16px, `--card-shadow-rest: none`, `border-border/80`) and overrides only the padding to the comp's 22px. The comp's 12px panel radius is not applied.
**Why**: `Card` is the app-wide locked card surface and its radius is a deliberate cross-archetype pick; re-declaring a second card shape 4px tighter inside the detail archetype would make two card radii coexist on the same page (a KPI tile and a dossier panel can appear in one view). One radius beats comp fidelity at this magnitude.
**Impact**: Recorded as a knowing deviation from KOPI_2A_SPEC "Cards → radius 12px". If `--card-radius` (already `0.75rem` = 12px in `src/index.css`) is ever wired into `Card`, dossier panels follow automatically and this entry is superseded.

## 2026-07-25 — The detail H1 takes the 38px step at the archetype, not in `PageTitle`
**Decision**: `PageShellHero` renders `<PageTitle className="text-[30px] md:text-[38px]">`; `PageTitle` itself keeps its locked 28px default for every other frame.
**Why**: The 2a type scale gives the archetypes different title steps (detail 38px, list 30px, masthead greeting 36px), so a single locked size cannot serve all three. `PageTitle`'s own rule — no `size` variants — is about preventing per-page drift; setting the size once per *archetype frame* keeps the family, weight and colour locked in the primitive where they belong.
**Impact**: Three frames may set a title size; no page may. If a fourth archetype needs one, add it to its frame, not to `PageTitle`.

## 2026-07-25 — Login is assembled from 2a's parts; the wordmark is the H1
**Decision**: `/login` renders on the page cream with a left-aligned header block — uppercase 11px `.14em` kicker (`ADVISOR SUITE`, `--fg-dim`) over the shared `Wordmark` lockup as the `<h1>` at 34px — then one `max-w-sm` cream `Card` carrying an Instrument Serif 22px "Sign in" section head, a `--border-soft` hairline, the two fields and a full-width brown primary. "Sign in" is the `<h2>`, not the H1.
**Why**: None of the three 2a comps draws a signed-out screen, so every value here is transplanted rather than invented: the kicker→serif→hairline order is the comps' own header block, 22px is the spec's section-head step, and the card is the standard `#FAF6EE`-on-`#F0E6D6` lift. Identity outranks the task on the only screen where the product has not yet introduced itself, so the wordmark takes the H1 and the form's own heading steps down — the same hierarchy the rail uses (wordmark above nav).
**Impact**: `Login.tsx` no longer uses `PageTitle` (a 28px locked H1 would have made the wordmark smaller than the detail archetype's title). The 34px lockup sits above the 18px Instrument Serif floor, so the italic word keeps the raw brand brown; `Wordmark`'s AA-darkened `accent` override is only needed below that.

## 2026-07-25 — Login's inputs step up to the raised white; the `Input` primitive does not
**Decision**: The two login fields pass `className="bg-popover"` (raised white `#FFFFFF`). The shared `Input` primitive keeps painting `bg-card`.
**Why**: KOPI_2A_SPEC → Inputs puts inputs on the raised token ("the only place white appears in the comp"). On this page the container *is* card cream, so an input painting `bg-card` dissolves into its own panel and only the hairline separates them — the surface ladder collapses. Everywhere else in the app inputs sit on the page ground or inside a `--secondary` fieldset, where card cream still steps up correctly, so repainting the primitive would have been a much larger change than the evidence supports.
**Impact**: A deliberate per-page override, not a fork of the primitive's other locked behaviour — focus stays the primitive's solid 2px brown outline rather than the comp's `border-color` + 3px halo, so the product keeps one focus language. If a future pass moves `Input` to `--popover` app-wide, delete the override here.

## 2026-07-25 — `AppHeaderShell` gains a `kicker`, and its header block always closes with a hairline
**Decision**: Additive optional `kicker?: string` (uppercase 11px `.14em`, `--fg-dim`) rendered above the H1, and the title block is now wrapped by `border-b border-[color:var(--border-soft)] pb-5` for every page, not as an opt-in.
**Why**: All three 2a comps close their header block with the structure hairline — masthead `padding-bottom:22px`, list header `16px`, detail header `20px` — so it is the archetype's rule, not a per-page decoration; gating it on the kicker would have encoded an arbitrary coupling. The kicker is the List/Dashboard comps' opening line; Detail-style pages lead with the breadcrumb instead and pass none, which is why the two are not rendered together.
**Impact**: `CrmDashboardPage` — the one adopter outside this slice — gains the hairline and nothing else; verified against the empty book. `kicker` is `--fg-dim`, not `--fg-muted`, because the header block paints straight onto the page cream (4.12:1), the spec's own "Open item — muted on page".

## 2026-07-25 — Account Settings: panels label themselves, the tab strip stays inside its panel
**Decision**: `/account-settings` opens with `kicker="Workspace · Account"`. `TabNav` remains the head of the cream panel it controls (`Card padding="p-0"`, body padded to the comp's 22px); the Security tab's two forms become `<section>`s split by a `--border-soft` hairline, each opening with the uppercase 11px `.12em` panel label (`EMAIL ADDRESS`, `PASSWORD`); the Session card drops `CardTitle`/`CardDescription` for the same panel label plus a reference-panel row (`Signed in as` → email) over a hairline.
**Why**: 2a mocks no settings screen. Two of its rules decide the shape: "every panel opens with the uppercase label" and "never nest boxed sub-cards — use a grid plus a hairline". The tab strip is not a nested box — it is the panel's own head with a rule under it — so it stays where it was and the tab wiring is untouched; the sub-sections that *were* heading-led become label-led sections instead of gaining sub-cards.
**Impact**: The panel labels ship as `<h2>`s so the page keeps a real heading outline under its H1 — the label is a type treatment, not a substitute for structure. `account-settings-tab-{profile,security}`, `account-profile-*`, `account-signout-btn` and `account-session-card` are all unchanged; `account-session-email` is new.

## 2026-07-25 — Portfolio report: print CTA on its own `.no-print` row, and the two states come from the comp
**Decision**: The Print / Save as PDF primary stays in the page body on a `.no-print` row directly under the header block (right-aligned, with a muted caption on the left once the query resolves) rather than moving into the header's action position. Loading becomes the comp's dashed placeholder (`--hairline-frame` dashed border, Instrument Serif 19px italic verb, 70% × 4px brown bar on the `--border-faint` track, 11.5px caption); the empty book becomes the comp's empty state — serif 20px italic line, one muted explanatory line, **one quiet secondary action**.
**Why**: The 2a Detail header puts actions top-right, but `report-print.css` requires every interactive affordance to sit inside a `.no-print` container and `AppHeaderShell`'s header is not one — fidelity here would have broken the print contract, which outranks it. The states are the spec's own: "Loading — a placeholder panel with 1px dashed…" and "Empty — … then **one** quiet secondary action. No illustration, no icon, no primary CTA", which is why the previous brown "Go to clients" primary is demoted to the outline variant.
**Impact**: The loading bar pulses at full width instead of filling to a percentage — the query reports no progress and a part-filled bar would state one it does not have; the spec's static 55% fill is a comp still, not a contract. The caption renders only once `data` exists, so "Nothing to print until the book has a client" can never appear over a pending query. `portfolio-report-{print,go-clients}-btn`, `portfolio-report-loading`, `report-portfolio-empty` and `report-portfolio` all keep their testids; the printed artifact is untouched.

## 2026-07-25 — The list table loses its card; `surface="bare"` is a DataTable mode, not a fork
**Decision**: `DataTable` / `DataRow` / `TableHeader` gain an additive `surface?: 'card' | 'bare'` (default `card`). `ListPageFrame` passes `bare`: no shell border/radius/fill, flush gutters, row hairlines carried as `border-top` with the header rule dropped so the two cannot double, hover as a solid card-cream step, and an inset focus ring.
**Why**: The 2a List comp draws its table straight on the page cream — a card there would be the nested boxed sub-card the layout language forbids. But the dashboard table and every card-mounted table still need the old treatment, so the mode is a prop on the shared primitives rather than a list-only copy of them. The hover had to change with it: `--row-hover` is a 6% brown wash tuned to read on card cream, and it is invisible against the page.
**Impact**: Every existing adopter is untouched (`card` is the default). Bare `muted` cells shift from `--fg-muted` to a 12px `--fg-dim` — `#7d6b5b` is 4.12:1 on the page ground and fails AA — so the meta step is carried by size, not by a lighter ink. `DataRowCell` also gains `tone` (positive/neutral/negative) for the comp's plain-text status column, always via the AA-safe text variants.

## 2026-07-25 — Search and the primary CTA move onto the list title row; FilterBar keeps the rest
**Decision**: `ListPageHeader` renders kicker → serif title + inline count, with a 220px `SearchInput` and the brown primary right-aligned on the same baseline row, closed by a `--border-soft` hairline. `FilterBar` gains `showSearch?: boolean` and is rendered by the frame ONLY when there are filter popovers or columns/export/clear controls.
**Why**: The comp's list header is one flex row — controls on the title line, no toolbar strip beneath. Deleting `FilterBar` from the frame would have stranded the filter/columns/export/clear affordances (and their testids), and duplicating a second search box was not an option, so the bar stays for the extras with its search suppressed.
**Impact**: `searchTestId` now lands on the title-row input; `exportTestId` / `columnsTestId` / `clearFiltersTestId` still land on FilterBar. Pages that pass none of the extras render no second row at all. The inline count is suppressed while `variant` is `loading`/`error` rather than flashing a "0". `kicker` is a new optional prop — the frame cannot invent it, so the three adopters pass their own ("Clients · CRM", "Results · Profiler", "Accounts · Admin").

## 2026-07-25 — Table state blocks drop the icon and gain exactly one quiet action
**Decision**: `DataTable`'s empty / no-results / error bodies lose the dashed icon circle and take an optional `stateAction` rendered as a single outline button. `ListPageFrame` derives it: "Clear search" when a search found nothing, otherwise the page's own create action when the list is genuinely empty.
**Why**: KOPI_2A_SPEC → States is explicit — "No illustration, no icon, no primary CTA" and "**one** quiet secondary action". The action has to be derived rather than invented, and both sources are already real props on the frame.
**Impact**: The error body tints only its headline (`--negative-text`), never the surface — 2a errors are row-level. The explanatory line moves from 11px `--fg-muted` to 12.5px `--fg-dim` so it clears AA on the bare list's page ground. Pagination stays on every list (server-bounded `.range()` is a hard rule) and is restyled flush — `bg-transparent px-0`, IBM Plex Sans + `tabular-nums` in place of the mono stack, which 2a does not use anywhere.

## 2026-07-25 — DISC is the one sanctioned categorical palette; it lives in `--disc-*` and is NOT the brown ramp
**Decision**: The four DISC hues keep their frozen legacy values (D `#c0392b`, I `#d4680a`, S `#1a7a40`, C `#1a5f8a`) and are promoted to named tokens in `src/index.css` under an explicit "DISC taxonomy — domain data, exempt from brown discipline" block. `CommunicationStyleRows` now reads those tokens (tint and border via `color-mix`, so nothing has to fall back to a raw literal). The profiler's `PR[].col` keeps the same hexes as **content** data.
**Why**: An adversarial pass proposed repointing them onto `--chart-ramp-1..4`. Declined — for the third time, and now recorded where the next pass will look. `--chart-ramp-*` is a SEQUENTIAL brown scale; using it for a 4-way categorical encoding takes DISC-C to `#dccbb6`, which is ~1.1:1 on cream and would destroy the wizard's selected-option border, the `ScoreCard` bar and the chip dot all at once. Trading a working affordance for palette purity is the wrong direction: contrast wins. The two earlier rulings are `src/features/profiler/lib/decisions.md`, 2026-07-25 entry 1 and entry 4.
**Impact**: Usage is tint + border + a decorative `aria-hidden` dot ONLY — the letter and the profile name always carry the meaning, so the ramp-constraint ("a mark may never be the sole carrier") is satisfied without the ramp. As solid marks on card cream the four measure 5.05 / 3.37 / 4.99 / 6.39:1, all clearing the 3:1 floor for non-text UI; they remain banned as text, which is why every DISC pill puts its letter on `--fg`. The CRM/profiler duplication stays — `no-cross-feature-imports` is a dependency-cruiser error — but both sides now point at one token block instead of two copies of four literals.

**Decision**: `DataRowCells`, `StatusTabs`' count pill, `MobileListCard`'s meta row, `FilterBar`'s active-filter chips and `Badge`'s count variant all move from `var(--font-mono)` to `var(--font-sans)` + `font-variant-numeric: tabular-nums`. `DataRowCell.mono` is kept as a prop and now means "tabular figures", nothing more.

## 2026-07-25 — Row interactivity is derived from `onClick`, never assumed
**Decision**: `DataRow` computes `clickable = !disabled && !!onClick` and gates the tab stop, `cursor-pointer`, the hover/active fills and the focus ring on it. A row with no handler renders inert (`cursor-default`, no tab stop).
**Why**: Every row was unconditionally `tabIndex={0}`. ## 2026-07-25 — `outline-none` may not sit on the same element as a `focus:outline-*` utility (Tailwind 4)
**Decision**: The bare-mode `<input>` in the `Input` primitive drops its standalone `outline-none`. The `focus:outline-2` / `focus:outline-[color:…]` utilities own the outline.
**Why**: In Tailwind 4 `.outline-none` emits `--tw-outline-style: none` **and** `outline-style: none`, while `.focus:outline-2` emits only `outline-style: var(--tw-outline-style)`. `--tw-outline-style` is an `@property` with `inherits: false`, so on the element that declared `none` the focus rule resolves back to `none` and the locked 2px brown outline never painted — on Login's email + password fields, the Account Settings forms and the wizard intake fields. **Impact**: Focus now paints the brown 2px outline at `outline-offset-1`, and the error variant its `--negative-text` outline. The slot-mode branch, `Select` and `Textarea` were never affected — there `outline-none` sits on the inner control and the `focus-within:outline-*` utilities on the container, so the custom property is set on a different element.

## 2026-07-25 — Light-only ships with the theme plumbing intact
**Decision**: Extends "Light-pinned, no dark mode" above. `ThemeProvider` pins `resolved = 'light'` and guarantees the `dark` class stays off `<html>`, but the surrounding machinery is deliberately **kept**: the `ThemePreference` / `ResolvedTheme` types, the `prefers-color-scheme` listener, and the `localStorage` key `w08:theme:v1` (unchanged since W08 Phase 1, so earlier picks survive).
